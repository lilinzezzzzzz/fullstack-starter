# 文档维护规则

适用于 `docs/`；同时遵循[根目录规则](../AGENTS.md)。修改根 README 或项目指令时也按下述职责保持一致。

## 内容归属

- [design.md](design.md) 描述当前架构、目录职责、固定契约和 V1 范围；方案尚未实现时明确标注，不从代码存在推断已验收。
- [configuration.md](configuration.md) 维护必填字段、单位、配置流、公开白名单及固定安全边界。字段来源核对 `backend/app/config.py` 与 `configs/app.toml`；配置数量如有变化，重新计算后更新，不沿用旧数字。
- [README.md](../README.md) 维护首次运行、常用开发与检查命令，作为各指南的入口；不重复详细流程。其他文档与 AGENTS 引用具体负责的文档，仅保留本范围必要命令。
- [project-creation.md](project-creation.md) 维护独立项目创建参数、复制与重命名边界；[database.md](database.md) 维护备份、恢复、迁移开发与升级步骤；[project-alignment.md](project-alignment.md) 维护已有项目对齐的通用方法，不承载具体项目的执行状态。
- [history.md](history.md) 保存带日期的实际变更与验证证据。保留历史路径、配置格式和命令的当时语义，不把历史记录批量改成当前写法；在当前文档中移除过时操作并指向新入口。

## 证据与检查

- 验证记录写明日期、环境、实际命令或可定位范围、结果、跳过项及原因；区分静态检查、单元测试、真实启停、浏览器和日常环境操作。没有执行的检查不补写成功，历史总数不代表当前通过数。
- 示例使用仓库相对路径、占位项目名与无敏感数据的临时资源；运行命令说明工作目录、配置和数据库目标，避免读者误将验证命令用于日常库。
- 跨目录变更同步相关文档：字段变化检查配置表与 TOML，API 变化检查生成类型，目录或入口移动检查 README 与 AGENTS 的路径。只在事实发生变化时更新当前设计，不为排版整理改写历史证据。
- README 的 `## 基于脚手架创建新项目` 与后续 `## 配置文件` 是创建器 `update_documents()` 的裁剪边界；保留这两个标题及顺序，教程范围内不要夹入应在副本保留的内容。改动后验证副本中的标题、端口与所有本地链接。
- Markdown 格式检查使用统一入口 `pnpm --dir frontend format:check`；需要整理时使用 `pnpm --dir frontend format`，覆盖前端文件、根 README、`docs/` Markdown 与各级 `AGENTS.md`，新增子目录自动纳入。
- 提交结果前检查本地链接、标题锚点、代码块语言与闭合、命令是否存在，以及 `git diff --check`。纯文档验证不能证明运行行为；没有相关代码变更时，不为文档整理启动日常服务或迁移数据库。
